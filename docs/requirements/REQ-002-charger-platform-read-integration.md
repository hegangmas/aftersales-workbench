# REQ-002：售后工作台查询充电桩管理平台数据

- 状态：需求讨论稿，待充电桩管理平台团队核对数据和接口方案。
- 提出方：售后工作台；接口提供方：充电桩管理平台。
- 日期：2026-11-25。
- 关联：[REQ-001 售后个人工作台](REQ-001-personal-workbench.md)。确认版本、接口文档与验收记录：待补充。
- 本文可直接交给充电桩管理平台开发任务；接口路径、字段名及具体实现由双方结合现有平台确认。

## 一、背景与目标

售后人员接到电话、微信群或其他渠道的问题后，通过桩编号或已有问题单查看设备信息。工作台需要从充电桩管理平台获取设备状态、最近充电记录和故障告警，辅助判断问题发生的时间及下一步排查方向。

首批以测试环境中的单桩查询为目标，提供只读数据，不执行远程启动、停止、重启、参数修改或其他设备控制。工作台现有页面中标注的模拟数据，在接口联调通过后才替换为实际查询结果。

## 二、查询入口与设备识别

- 首批按桩编号查询；已有问题单可使用其关联桩编号。
- 请平台方确认平台桩编号、设备编号、铭牌编号、枪编号的对应关系，以及设备更换、重编号和一桩多枪的识别方式。
- 手机号查设备属于后续可选能力，涉及一人多桩、非车主来电和客户信息来源，需另行确认；本次不要求平台提供手机号检索。
- 当查询结果可能匹配多台设备时，请返回可供确认的候选信息，不自动选定。

## 三、首批数据需求

### 3.1 设备基本信息和当前状态

**用途：**确认设备，并判断在线、运行和枪口状态。

| 数据项 | 说明 |
| --- | --- |
| 桩编号及平台内部设备标识 | 明确查询标识和返回标识的关系 |
| 型号、产品类型 | 如交流桩、直流桩；无可靠数据时为空 |
| 场站名称及地址 | 平台有则提供；安装资料后续以智享乐装为准 |
| 枪号及枪状态 | 多枪分别返回；注明状态来源和时间 |
| 在线状态 | 在线、离线或未知，并说明判定口径 |
| 当前运行状态 | 如空闲、充电中或故障，保留平台原始状态 |
| 最后通信时间、状态更新时间 | 便于判断数据是否过期，无法取得时为空 |

### 3.2 最近充电会话或充电订单

**用途：**判断问题发生于启动前、充电过程中还是结束时，并与故障时间对照。

建议默认最近 30 天、最多 10 条，按时间倒序，支持指定时间范围和枪号；具体限制由平台团队结合数据规模确定。

| 数据项 | 说明 |
| --- | --- |
| 会话或充电订单编号 | 便于追查；说明与平台其他订单编号的关系 |
| 桩编号、枪号 | 明确设备和枪口 |
| 开始时间、结束时间 | 进行中的记录结束时间可为空 |
| 充电状态 | 进行中、结束或异常等，以实际状态为准，保留原始值 |
| 充电时长、充电电量 | 注明单位；未知值为空，不用 0 代表缺失 |
| 启动方式 | 有可靠数据则提供 |
| 停止原因／结束原因 | 有则返回原始代码和可读说明，不自行推断 |
| 关联异常 | 仅在平台有可靠关联时提供 |

**源码核对提醒：**本地平台源码中的 `ChargeRecord` 实体实际描述账户充值，包括支付和余额字段，并非已确认的设备充电会话。请平台方确认实际的充电订单或会话表及接口，避免混淆。

### 3.3 当前故障和历史告警

**用途：**查看当前故障及历史告警，与充电时间对照。

建议优先展示当前未恢复故障，再查询最近 30 天的历史记录，默认最多 20 条；支持按时间和枪号筛选。

| 数据项 | 说明 |
| --- | --- |
| 桩编号、枪号 | 区分桩级与枪级，枪号未知时为空 |
| 故障／告警原始代码 | 保留上报值 |
| 名称或说明 | 平台有可靠字典时提供；无法解析时保留原始码 |
| 级别 | 原始值及可读名称；注明字典来源 |
| 上报时间、恢复时间 | 未恢复时恢复时间为空 |
| 故障状态 | 故障中、已恢复或未知；说明状态口径 |
| 来源及更新时间 | 区分设备上报、平台计算或其他来源 |

本地源码中的 `Fault` 实体包含桩编号、枪号、故障码、级别、上报时间、恢复时间和状态；是否与当前部署、实际数据及接口一致，仍需平台方验证。

## 四、接口和数据约定

可提供三个独立只读接口：设备概况、充电会话、故障告警；也可复用现有接口或提供聚合接口。建议各类数据支持独立失败，避免一个来源不可用时影响其他结果。具体路径、请求与响应结构由平台方提出。

- 使用独立测试调用身份及最小必要权限；认证和部署方式由双方确认，不将凭据写入仓库。
- 返回来源与查询时间；说明时间的时区，建议使用带时区时间。
- 明确区分查询成功但无记录、设备不存在、权限不足、服务暂不可用；未知、空值和 0 的含义须明确。
- 列表限制条数、按时间倒序；必要时提供分页或游标。
- 编号、状态和故障码保留原始值；提供可信字典时同时返回可读说明。
- 字段以实际平台能力为准，不存在的字段注明不可提供；不要伪造或推断。
- 不提供售后排障不需要的支付、余额等信息。

## 五、异常场景与工作台处理

1. 找不到桩：提示编号未匹配，允许售后人员核对编号并继续原有问题单流程。
2. 部分接口失败：保留其他已成功取得的数据，失败区域提示暂不可用及可重试。
3. 确实无记录：显示无记录，不与接口失败混淆。
4. 数据过旧或时间未知：展示最后通信／更新时间或未知，不能据此宣称当前实时状态。
5. 权限不足：明确提示无权查询，不将其解释成无记录。

## 六、联调资料

请平台方提供测试环境中可查询的一台或几台桩，以及：

1. 测试桩编号及对应的枪口、平台页面查询方式。
2. 对应正常和异常充电会话，以及未恢复和已恢复故障的预期样例；没有相应样例时说明。
3. 接口地址、认证方式、脱敏请求／响应示例、字段含义、枚举及时间口径。
4. 哪些字段不存在、数据刷新频率和可追溯的原页面或记录。
5. 售后测试虚拟机到平台的可达路径，以及接口访问所需的网络配置。

## 七、验收标准

- 使用同一测试桩，设备编号和多枪对应关系与平台原页面一致。
- 至少一条充电会话的时间、电量及可获得的结束原因与平台原页面或记录一致；无异常样例时说明未覆盖。
- 至少一条故障的代码、上报时间和恢复状态与平台原页面或记录一致；无故障样例时说明未覆盖。
- 验证设备不存在、无记录、权限不足和服务不可用时的区分，以及部分接口失败时其他数据仍可展示。
- 验证仅能查询，不触发设备控制或修改平台数据。
- 记录测试环境、代码／接口版本、时间、样例、结果和未覆盖项，由双方确认。

## 八、后续范围及待确认事项

第二批可评估电压、电流、功率曲线、BMS 与通信异常、固件版本、参数变更和离线心跳历史。需先确认平台是否保存、采样粒度和业务用途，再形成独立需求。

MES 的出厂测试及厂内返修、智享乐装的安装和现场维修、400 通话及录音分别属于其他系统或待确认能力，不要求充电桩管理平台在本次接口中提供。
