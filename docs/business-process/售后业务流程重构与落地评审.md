## 一、售后业务主线

工作台管理“售后问题”。一次问题可关联多次电话、群消息和材料，也可关联一张或多张先后发生的现场任务。智享乐装管理正式现场派修、现场执行、完工及结算。设备的运行事实来自充电桩管理平台，出厂和厂内返修事实来自 MES。客户再次联系时先查同一问题，设备档案则贯穿各次问题。

| 节点 | 谁主办 | 工作与流转 | 必留记录 |
| --- | --- | --- | --- |
| B01 受理 | 坐席，未认领时由队列值班负责人兜底 | 400、群聊、服务商、小程序或车企入口进入受理队列。首版可代录，已有 AI 入口可择一验证。记录在手即可受理 | 来源、来源编号或人工流水、接触时间、现象、回访方式、项目或待核实标记 |
| B02 识别与关联 | 坐席 | 手机号或 SN 搜索候选，核对项目、安装地点、事发时间和当时设备。相同问题关联已有记录，两个不同现象分别建问题 | 当前设备与事发设备、身份核实结果、关联依据。识别不清时留回访任务 |
| B03 分级取证 | 一线售后，安全事件转具备资质人员 | 一般咨询可直接答复收尾。故障先判风险，再围绕事发时间读取运行证据和安装维修摘要，必要时补 MES。烟味、冒烟、触电等信号可在 B01 或任一后续节点立即升级 | 风险及来源、查询范围、证据链接、缺项、适用 SOP 版本 |
| B04 决策与远程处理 | 一线或二线，按项目权限 | 从安全远程指导、补证、二线会诊、申请现场服务中选择。每次转交写清要回答的问题。远程措施执行后进入 B07 | 措施、操作者、执行结果、回访或复测要求。设备控制按既有权限和流程执行 |
| B05 等待与接续 | 当前问题负责人或值班组 | 客户暂不在现场、上游缺数据、等二线判断等，记录原因、下次动作、截止时间。新消息、约定到期或补证均可触发续办。高风险升级可与等待并行 | 当前负责人、下一步、到期时间、交接双方或负责值班组 |
| B06 现场服务 | 授权派单人、服务商、审批人 | 先确认要验证的事项和责任方，再在智享乐装派单。上门查验、换件、换桩按各自条件执行。取得明确回执后进入 B07，退回或取消交原责任组处理 | 实际工单号、预约与节点、现场发现、实际动作及原／新部件标识。换桩保留审批和退件线索 |
| B07 验证 | 问题负责人，技术人员提供复核 | 根据故障类型检查实际恢复。经确认恢复或已答复的咨询进入 B08。未恢复回 B03／B04。尚不可验证则进入 B05 | 验证时间、方式、证据及结论。升级、指令下发、上门和完工是过程记录 |
| B08 结束与复盘 | 问题负责人、质量人员 | 按已验证恢复、咨询完成、重复并入、非本公司受理、按规则结束未解决等原因归档。复发与前次关联，实际误关由授权人员重开。需要返厂或质量调查的形成独立后续任务 | 结束原因、客户告知记录、未验证标记、后续质量任务编号 |

典型路径可用同一个演示案例拆成四个变体：

1. 坐席查到预约配置符合客户所述，按已审核指引说明。客户后续成功启动，记录验证结果后结束。
2. 客户晚上才到现场，一线保留约定时间。第二天换班，接班人从队列接手，看到上次问了什么与需要核实哪项。
3. 远程证据不足以区分车端、桩端或现场供电，二线提出现场查验任务。服务商提交回执，售后根据回执及充电记录验证。
4. 服务商已完工但客户仍报同一现象，原问题回到排查。电话关联原记录，必要时建立一张新的现场任务并关联首次上门。

## 二、会中流程的修正项

下表区分会议中的方案与拟采用的流程规则。定位时间供复听。

| 编号 | 会议方案或缺口 | 可能发生的业务错误 | 拟修正规则 |
| --- | --- | --- | --- |
| R01 | 多渠道进入工单池并生成编号，08:59；既有系统衔接见 01:19 | 一次客户问题同时从群和 400 进来，重复跟进、重复派人 | 渠道联系和问题分别编号。入口事件按来源去重，相同业务问题只提示候选，由坐席核实后关联。智享乐装保留正式现场单号 |
| R02 | 优先用手机号触发，26:47 起 | 来电人是家属或服务商。一号多桩、换桩后查到旧记录 | 手机号仅作检索线索，核项目、安装和有效期后确认。疑似错绑保留人工核实 |
| R03 | 取数图只列受理时的信息，会议另提实时故障报文，00:35 | 诊断时看不到运行证据，处理后也无法验证 | 首次读运行摘要，诊断和恢复时可刷新，保留原证据快照。标明空结果、未覆盖、无权限、失败 |
| R04 | 原图呈线性步骤，会上讨论简化结束和升级换序，01:16–01:17、01:36 | 简单咨询也要求派修，超时或安全升级等待前序节点 | 按咨询、远程、等待、二线、现场分支。升级和超时是可横跨阶段的事件，升级成功须取得接手确认或保留原责任人 |
| R05 | 挂起开放给全员，00:38 | 大家可见，没人回访。换班后重新建单 | 共享可见＋值班兜底＋到期待办。接班认领与旧负责人释放一次完成 |
| R06 | A/B/C 同时反映证据和客户配合，01:14–01:16 | 客户拒传视频时机械拒绝服务，或看到报文就批准换桩 | 独立记录紧急程度、证据充分性、客户当前配合条件及处置授权。资料不足仍可转专业复核、约回访或获准现场查验 |
| R07 | 统一要求客户自行上传资料，00:45–01:03 | 老人、不在现场、网络差或无合适设备时卡住 | 先复用后台，按故障索取能改变决定的一项材料，可代传或由现场补证。换件等动作由适用规则规定必要证据 |
| R08 | 自动审批换桩和返厂检验，01:16、00:57 | 模型误批、成本责任未确定。返厂未复现被误作错派结论 | 首轮人工审批，AI 整理证据。记录技术依据和项目授权。复盘保留检测条件、复现结论及旧新 SN，按条件复核 |
| R09 | 智享乐装完工、节点回写，01:19–01:28 | 上门完工后客户问题仍在。回传丢失时显示假状态 | 执行状态和问题状态各有归属。完工进入待验证。回传失败可重查并说明更新时间 |
| R10 | 400 自动取数、群统一企微、车企平台接入，00:09–00:26、00:41 | 供应商接口、客户授权或平台权限未落实，首版无法启动 | 保留手工受理，逐渠道做授权样例验证。特殊车企按认可入口和既有作业处理 |
| R11 | 休息在岗与强制均分，01:38–01:44 | 池外工作不可见，多单落到忙碌人员或技能不匹配 | 首轮按值班认领，主管看紧急、到期和无人认领。后续规则再纳入项目权限、技能、容量、等待类任务及池外负荷 |
| R12 | 2 小时、5 分钟等时效示例和自动升级，01:31、01:38 | 把渠道承诺、内部升级和人工工时混用 | 按项目与渠道确认首次有效联系、下次回访及升级的各自起止。等待仍保留客户实际历时 |
| R13 | 旧流程节点可跳到第 7 步，01:36 | 简单咨询被当成已修复或进入现场派修 | 直接答复并使用“咨询完成”等原因结束。故障仅在验证满足后标记恢复 |
| R14 | 小程序补传、查进度、催单，01:25–01:36 | 客户跨单看到地址和附件，催单产生重复工单 | 后续试点采用已认证客户和工单范围校验。补传、查进度、催单复用原问题编号，线上报价支付沿用正式交易流程 |

## 三、可能卡在现场的情形与落地方案

| 卡点 | 坐席立即怎么处理 | 后台和组织怎么配合 | 用什么确认能跑通 |
| --- | --- | --- | --- |
| 来电号与登记号不同、SN 读不全 | 先受理，再补问地点或标签等核验线索。信息不全先约回访 | 支持候选列表、项目过滤、建立待识别的临时问题，避免错绑变为长期档案 | 用一号多桩、换桩两例，演示未确认前的遮罩与核验记录 |
| 设备离线、日志迟到、平台异常 | 告知已有事实和时间，先做可确认的问询。相同区域集中异常关联同一个平台事件 | 时间线显示最后通信、采集时间和来源状态。平台排障提供事件编号和更新时间 | 对同一案例注入超时、空结果、迟到数据，确认各界面文字和续办行为 |
| 客户晚上才方便、连续联系 | 明确与客户约定时间，填写下一步。再来电时从原问题续办 | 提醒进入接班组，主管看逾期和无人接单，记录实际联系结果 | 两班次演示客户再次来电和回访到期两种触发 |
| 客户不上传或现场存在安全信号 | 采用可替代证据，必要时转专业人员。风险明确时优先按审核过的安全流程处理 | 周志磊牵头明确定义必需证据、替代证据和升级条件，研发、质量评审 | 安全信号、无照片、二线退回补充三个案例 |
| 上门拒单、取消、找不到现场单 | 负责人收到待办，核对原因，再决定改派、约期或转远程 | 同一送单请求保留唯一键，超时先查；回执状态留原值、映射状态和最后同步时间 | 模拟送单超时、成功但回包丢失、重复回执和取消后到达旧回执 |
| 师傅完工但桩仍不能用 | 保留原问题，补充上次现场结果，重新排查或申请再次上门 | 售后问题与现场执行分开计数，记录是否首次到场修复和处理后恢复证据 | 完工未恢复和恢复后二次复发各一例 |
| 400 或群助手接不了、车企数据受限 | 按现行渠道答复，工作台登记必要摘要并保留允许引用的编号 | 经授权的测试样例验收来源、重复事件、转人工和数据范围 | 一个外包通话、一条群报修、一个受限车企渠道的手工入口 |
| 换桩后返厂无故障 | 现场、技术、质量各补充自己掌握的事实，必要时复盘同批次 | 串联旧新 SN、条件和版本，返厂测试结果原样保存 | 用“本次未复现”样例确认统计和页面口径 |

## 四、启动时由售后拍板的事项

| 谁 | 需要确认的事项 | 判断已经准备好的证据 |
| --- | --- | --- |
| 吴超 | 试点型号、渠道、值班组、转二线条件，哪些项目可接触车主和发起派修 | 一页项目规则及接班表。项目服务时限有来源和生效日 |
| 周志磊及一线骨干，联合质量和研发 | 故障分类、远程可指导范围、最低证据、替代证据、换件换桩审批和恢复验证 | 一份适用试点型号的已审核 SOP。至少有“证据不足但可上门核实”的案例 |
| 何刚指定开发执行人、信息部对接人 | 三源查询字段、授权数据环境、智享乐装工单状态归属、群内助手已实现的能力 | 一个真实 SN 与三源对账，一台换过桩的设备档案，一次现有工单流转演示 |
| 吴超、400 服务商及系统对接人 | 录音、话单、事件推送、字段遮罩、匹配能力 | 一条授权通话样本。首轮手工接待可独立运行 |
| 吴超与试用坐席 | 样本、验收门槛、上线及复盘日期 | 建议准备 10–20 条历史样本、2–3 位坐席。分三种方式记录人工时间，配套观察恢复、重复联系、误派单 |

首次演示通过的标志是同一案例经过两位坐席、只查对一台事发设备、保留技术依据并完成恢复验证。现场回执、自动接入和客户自助各用自己的样例验收，再决定投入顺序。
